## Editor scripting: Python plugin, Interchange import, Sequencer/MovieScene, Movie Render Graph

### Takeaway
Python (embedded CPython 3.11.8 per current docs) remains editor-only but can run headless via `-run=pythonscript`; Interchange is the default importer (5.4/5.5 onward, sources conflict) and is scriptable via pipeline assets; Sequencer exposes `LevelSequenceEditorSubsystem.create_camera()` which creates a spawnable camera plus camera-cut track; Movie Render Graph is the scripted render path and is the successor to Movie Render Queue, but headless `-game` rendering with MRG had community-reported limits in the 5.5 era.

### Cited Findings
**Python plugin**
- The Python Editor Script Plugin "contains an embedded version of Python 3.11.8" (current unversioned docs); a different Python can be embedded by setting `UE_PYTHON_DIR` and rebuilding from source; the plugin must be enabled per project; Epic recommends also enabling Editor Scripting Utilities; Python "is only available in the Unreal Editor, not when your Project is running in Play In Editor, standalone, or cooked builds" — [Epic docs: Scripting the Unreal Editor Using Python](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python)
- Headless: "Option 2: Commandlet ... can even run your scripts in headless mode without opening the Editor UI"; syntax `UnrealEditor-Cmd.exe <project> -run=pythonscript -script=<script_file_or_code>`; the commandlet "does not automatically load levels"; the alternate `-ExecutePythonScript` route requires the Editor Scripting Utilities plugin — [Epic docs](https://dev.epicgames.com/documentation/unreal-engine/scripting-the-unreal-editor-using-python)
- Community-reported working headless command: `UnrealEditor-Cmd.exe "Project.uproject" -run=pythonscript -Script="Script.py" -unattended -nullrhi`; other users report scripts that work in-editor crash under the commandlet and fall back to the full editor binary with `-nullrhi` — [Epic forum](https://forums.unrealengine.com/t/executing-python-script-from-outside-the-editor/686226); [Epic forum (UE4-era)](https://forums.unrealengine.com/t/interacting-with-ue4-editor-by-commandline-best-practice/437852)
- FRAGILE (5.6): a new `check(IsInGameThread())` in `FEditorScriptExecutionGuard::FEditorScriptExecutionGuard` was added in 5.6 and "breaks Python running on a background thread"; the poster says the change is not in the release notes — [Epic forum](https://forums.unrealengine.com/t/unreal-5-6-no-longer-allows-python-to-run-on-a-background-thread/2675284)

**Interchange vs legacy FBX**
- Forum users state Interchange replaced the legacy FBX plugin by default "from UE 5.4 onward"; others say it was turned on by default in 5.5 (sources conflict); one explanation: "Interchange is enabled by default because Fab plugin requires it and is enabled by default" (plugins: Interchange, InterchangeAssets, InterchangeEditor) — [Epic forum: FBX import changed?](https://forums.unrealengine.com/t/fbx-import-changed/2144275); [Epic forum: UE 5.5 Released thread](https://forums.unrealengine.com/t/unreal-engine-5-5-released/2117936/14)
- Older official docs (version unclear) say "FBX support is currently experimental" behind console flag `Interchange.FeatureFlags.Import.FBX`; users on 5.5/5.6 use `Interchange.FeatureFlags.Import.FBX=False` in `DefaultEngine.ini` `[ConsoleVariables]` to route FBX back to the legacy importer; disabling the whole Interchange plugin in 5.5 "also disables Mesh Painting" — [Epic docs: Importing Assets Using Interchange](https://dev.epicgames.com/documentation/de-de/unreal-engine/importing-assets-using-interchange-in-unreal-engine); [Epic forum](https://forums.unrealengine.com/t/fbx-import-changed/2144275?page=2); [Epic forum: Interchange cvar settings in 5.4](https://forums.unrealengine.com/t/interchange-cvar-settings-in-5-4/2481746)
- Interchange static-mesh gotchas (5.5): default Static Mesh pipeline "defaults to 'Recompute Normals'" discarding DCC smoothing; UCX collision meshes must now be children of the render mesh or they import as separate static meshes; with "Combine Static Meshes" off, meshes were named after internal geometry IDs (Epic staff reproduced and ticketed); bug UE-239476 expected fixed in 5.7 — [Epic forum](https://forums.unrealengine.com/t/ue-5-5-interchange-throws-away-imported-mesh-normals-really-bad-default/2313203); [Epic forum](https://forums.unrealengine.com/t/ue-5-5-interchange-fbx-importer-issues/2512392); [Epic forum](https://forums.unrealengine.com/t/ue-5-5-fbx-interchange-importer-naming-regression-with-combine-static-meshes/2429945); [Epic forum](https://forums.unrealengine.com/t/5-5-static-mesh-import-pipeline-regression/2551048)
- Python/Interchange: `unreal.InterchangeGenericAssetsPipeline` has `import_lods` ("requires the advanced bBakeMesh property to be enabled") and "should be called before specialized mesh pipelines"; to force a pipeline, load `/Interchange/Pipelines/DefaultAssetsPipeline` and append it to the import parameters' override pipelines; `AssetImportTask` picks the importer by file extension; pipeline asset defaults can be edited from Python via the editor asset subsystem — [Epic Python API: InterchangeGenericAssetsPipeline](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/InterchangeGenericAssetsPipeline); [Epic forum (UE 5.1)](https://forums.unrealengine.com/t/python-or-blueprint-example-for-importing-obj-file-in-ue5-1-interchange-import-pipeline/714987)
- With `import_scene` "it's still possible to get the list of imported objects but you need to register a callback on the import parameters" (Epic developer reply, 5.6 thread) — [Epic forum](https://forums.unrealengine.com/t/interchange-usd-import-in-ue-5-6-unsupported-schemas-incomplete-blueprint-conversion-block-production-adoption/2653604)

**Sequencer / MovieScene scripting**
- Epic's Sequencer Python docs: get the `LevelSequenceEditorSubsystem` and call `create_camera(spawnable = True)`, which adds a spawnable camera binding along with a camera cut track, "mimicking the process through the Sequencer UI" — [Epic docs: Python Scripting in Sequencer](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-scripting-in-sequencer-in-unreal-engine)
- Lower-level community path: create the sequence via `AssetToolsHelpers`, spawn a `CineCameraActor` with `EditorLevelLibrary`, call `add_spawnable_from_instance` on the sequence, then add a possessable binding for the `CineCameraComponent` ("create a camera, create a spawnable from it, and then get the camera component from the camera and add a possessable binding to it") — [Epic forum](https://forums.unrealengine.com/t/add-cinecameracomponent-to-spawnable-cinecameraactor/481841); related issue [UE-79406](https://issues.unrealengine.com/issue/UE-79406)
- Camera Cut Track is bound to a camera through Camera Cut sections; each cut is a separate section — [Epic docs: Cinematic Camera Cut Track](https://dev.epicgames.com/documentation/unreal-engine/cinematic-camera-cut-track-in-unreal-engine)

**Movie Render Graph / Movie Render Queue**
- MRG is "the successor of Movie Render Queue", node-based, with configs backed by a graph editor; Epic's programming guide shows getting a job's graph preset, reading variables and overriding exposed variables (e.g. output resolution); example files are in the engine's MovieRenderPipeline Python content folder — [Epic docs: Programming a Render in MRG](https://dev.epicgames.com/documentation/unreal-engine/programming-a-render-in-mrg-in-unreal-engine?lang=en-US)
- `UMovieGraphScriptBase` "can be implemented in either C++ or Python" (Python versions as a Python-defined UClass), used by the Execute Script node; `help(unreal.MovieGraphScriptBase)` lists overridables — [Epic API docs (5.5)](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/MovieRenderPipelineCore/Graph/Nodes/UMovieGraphScriptBase?application_version=5.5)
- `EMoviePipelineConfigMode` has three modes: Preset (legacy `UMoviePipelinePrimaryConfig`), Graph (`UMovieGraphConfig`), Basic — [Epic API docs](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/MovieRenderPipelineCore/EMoviePipelineConfigMode)
- MRQ -> MRG migration: file naming moved to the File Type Output node; temporal/spatial sampling split between nodes; render path (Path Tracer or Deferred) set per render layer; "UI Renderer" listed as currently unsupported in MRG; some doc pages still label MRG beta — [Epic docs: Transitioning to MRG](https://dev.epicgames.com/documentation/en-us/unreal-engine/transitioning-to-the-movie-render-graph-from-movie-render-queue-in-unreal-engine); [Epic docs: Movie Render Pipeline](https://dev.epicgames.com/documentation/ko-kr/unreal-engine/movie-render-pipeline-in-unreal-engine)
- Community (5.5-era logs): "the Python-based runtime executor only works with `-game`, and MRG isn't supported in `-game` mode"; users ran MRG renders from the editor command line and needed `unreal.EditorPythonScripting.set_keep_python_script_alive(True)` to keep the editor alive — [Epic forum: Movie Graph Editor Python from CMD Line](https://forums.unrealengine.com/t/movie-graph-editor-python-from-cmd-line/2506983)

### Inferences
- A shot-list-to-Level-Sequence product can be built entirely in Python: create the LevelSequence asset, `create_camera(spawnable=True)` per shot (or spawn CineCameraActors and bind), key transform and `CineCameraComponent` focal length via MovieScene channel APIs, then submit an MRG job. Exact channel-keying function names were not confirmed by any snippet and must be checked against the version's Python API reference.
- Headless rendering should be designed as "editor binary launched with -nullrhi/-unattended running a Python script that drives the MRG queue", not a `-game` runtime executor, until Epic documents MRG in `-game`.
- Expect per-version breakage: Interchange defaults (normals, collision naming), the 5.6 game-thread check, and shifting MRG docs labels all changed between 5.4 and 5.7.

- Official statement of the version in which Interchange FBX became default/production for static meshes (forum sources conflict 5.4 vs 5.5); whether the legacy FBX importer is deprecated/removed by 5.8.
- Exact names of MovieScene channel-keying APIs for focal length (e.g. on `CineCameraComponent` property tracks) — not surfaced; mark unverified.
- Whether MRG became officially "production-ready" and in which release; whether `-game` MRG rendering is supported in 5.7/5.8.

## Remote control, browser surfaces, headless modes, UEFN/Verse, Horde/UGS, and the new Unreal MCP plugin

### Takeaway
Unreal exposes an HTTP (default port 30010) and WebSocket (default 30020) Remote Control API driven by Remote Control Presets, Pixel Streaming 2 for browser viewing (with reported gaps), the `-run=` commandlet path for headless jobs, and, new in 5.8, an experimental first-party MCP server inside the editor process (loopback HTTP, port 8000, `/mcp`). Horde and UnrealGameSync are Epic's build/sync stack; UEFN/Verse is a separate target under different legal terms.

### Cited Findings
**Remote Control API**
- WebSocket server defaults to port 30020 (`ws://127.0.0.1:30020`), configurable in project settings; messages are JSON with `MessageName`, `Parameters`, optional `Id`; an `http` message type tunnels HTTP routes (example `PUT /remote/object/property`); `preset.register`/`preset.unregister` subscribe to preset events `PresetFieldsAdded`, `PresetFieldsRemoved`, `PresetFieldsRenamed`, `PresetFieldsChanged`; docs ship a sample HTML/JS test page — [Epic docs: Remote Control API WebSocket Reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-api-websocket-reference-for-unreal-engine)
- HTTP preset routes on port 30010: `GET /remote/presets`; `GET /remote/preset/{name}`; `GET|PUT /remote/preset/{name}/property/{property}`; `PUT /remote/preset/{name}/function/{function}`; `GET|DELETE /remote/preset/{name}/metadata/{key}` — [Epic docs: Remote Control Preset API HTTP Reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-preset-api-http-reference-for-unreal-engine)

**Pixel Streaming**
- Pixel Streaming 2 streams "Unreal Engine audio and rendering to WebRTC-compatible media players such as a web browsers"; introduced from UE 5.5 with a new internal WebRTC layer; both the original plugin and PS2 ship during migration — [Epic API: PixelStreaming2 (5.6)](https://dev.epicgames.com/documentation/unreal-engine/API/PluginIndex/PixelStreaming2?application_version=5.6); [Epic forum: Pixel Streaming 2, Migrating and Key Notes](https://forums.unrealengine.com/t/pixel-streaming-2-migrating-and-key-notes/2175491)
- Vendor (Eagle 3D Streaming) reports: browser-to-Unreal / Unreal-to-browser messaging "currently not supported with Pixel Streaming Plugin 2" on 5.5/5.6 (PS1 supports it 5.1-5.7); apps on 5.5/5.6 with PS2 may negotiate WebRTC but the video stream fails to start — [Eagle3D compatibility](https://docs.eagle3dstreaming.com/wiki/pixel-streaming-plugin-2-compatibility); [Eagle3D blog](https://www.eagle3dstreaming.com/blog/pixel-streaming-vs-pixel-streaming-2-in-unreal-engine-5-the-beginner-guide)
- The PixelStreamingInfrastructure repo (signalling, SFU, web frontend) is separate from the engine plugin, with branches per UE version and npm frontend packages for 5.5/5.6/5.7 — [GitHub EpicGamesExt/PixelStreamingInfrastructure](https://github.com/EpicGamesExt/PixelStreamingInfrastructure)

**Unreal MCP (5.8, experimental)**
- Epic docs: "Unreal MCP embeds an MCP server inside the Unreal Editor process so that any MCP-compatible AI agent, such as Claude Code, Cursor, or the MCP Inspector, can drive the editor over a local HTTP connection" — [Epic docs: Unreal MCP in Unreal Editor](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-mcp-in-unreal-editor)
- Epic forum announcement for 5.8 describes the MCP plugin as connecting LLMs to the engine for automated asset creation, testing, and optimization — [Epic forum: UE 5.8 Released](https://forums.unrealengine.com/t/unreal-engine-5-8-released/2729274)
- Third-party write-ups of the docs: settings at Edit > Editor Preferences > General > Model Context Protocol; defaults port 8000, URL path `/mcp`, Tool Search enabled (initially exposes meta-tools `list_toolsets` and `describe_toolset`); "AllToolsets" enables bundled toolsets; relies on a Toolset Registry and an "Editor Tools" plugin; Epic "notes that APIs and data formats may change"; described as loopback-only with no authentication — [dev.to guide](https://dev.to/gamedevtoollab/using-unreal-mcp-in-ue-58-from-codex-setup-toolsets-and-safe-editor-automation-4pon); [StraySpark blog](https://www.strayspark.studio/blog/epic-official-mcp-plugin-ue5-8-vs-third-party)
- Third-party MCP servers (ue-mcp, UnrealMCP on PyPI, Unreal-MCP) exist and target earlier versions (e.g. 5.5+); they are not Epic products — [ue-mcp README](https://cdn.jsdelivr.net/npm/ue-mcp@1.3.8/README.md); [PyPI unrealmcp](https://pypi.org/project/unrealmcp/1.1.0/)

**Horde / UnrealGameSync**
- UGS is a front end for syncing a project from Perforce; the graphical client is Windows-only, with a command-line version for macOS and Linux; Horde's build automation can generate editor builds centrally and UGS's "Sync Precompiled Binaries" downloads them; a default Perforce server can be set in Horde's `globals.json`; storing precompiled binaries as zips in Perforce is "no longer necessary" — [Epic docs: Horde UnrealGameSync Tutorial](https://dev.epicgames.com/documentation/en-us/unreal-engine/horde-unrealgamesync-tutorial-for-unreal-engine); [Epic docs: Horde and UGS Metadata Server](https://dev.epicgames.com/documentation/en-us/unreal-engine/horde-and-unrealgamesync-metadata-server-for-unreal-engine)

**UEFN / Verse**
- UEFN v36 (June 2025) introduced Scene Graph beta; v29 (Sept 2024) an enhanced persistence system; developers report Scene Graph prefabs must be re-saved on every Verse compile (Epic reply: intentional to prevent data loss on breaking class changes; a Data Recovery Tool exists for Scene Graph only) — [UEFN Central version history](https://uefncentral.com/uk/uefn-version); [Epic forum](https://forums.unrealengine.com/t/scene-graph-prefabs-need-to-be-resaved-every-time-verse-is-compiled/2655176/4)
- UEFN, Verse code and island content fall under the Fortnite Developer Rules/Terms, not the Unreal Engine EULA — [Epic: UE devs can now choose to train AI models](https://unrealengine.com/ue-devs-can-now-choose-to-train-ai-models-on-their-projects); [Game Developer](https://www.gamedeveloper.com/programming/epic-is-updating-the-eula-to-allow-ai-training-on-outputs-from-unreal-engine-and-metahuman)

### Inferences
- For a browser-driven SaaS, the lowest-friction "plug in" is a thin UE plugin that exposes a Remote Control Preset (functions + properties) consumed over WebSocket 30020/HTTP 30010 from the web app, with Pixel Streaming (PS1 if two-way messaging is needed on 5.5/5.6) for the viewport. Both Remote Control and Unreal MCP are loopback/LAN-oriented with no auth; a SaaS needs its own tunnel/agent layer.
- The 5.8 MCP plugin is the Epic-sanctioned surface for agentic editor control going forward, but "experimental, APIs may change" means a product should wrap it behind an adapter rather than bind to its tool schemas.

- The general (non-preset) HTTP reference (e.g. `/remote/object/call`, `/remote/object/property`, `/remote/info`) was not read; only the WebSocket doc's `/remote/object/property` example confirms object routes exist.
- Web Remote Control UI (Remote Control Web Interface/Web App) status in 5.6-5.8: no results surfaced; unverified.
- Pixel Streaming 2 behaviour in 5.7/5.8 (whether messaging gap and video-start bug were fixed): unverified.
- Horde licensing/production status and any 5.6-5.8 changes: not found.
- UEFN 2026 release notes and any 2026 Verse/Scene Graph status: not found (newest version-history entry seen was Nov 2025).

## Collaboration: Multi-User Editing, source control integrations (Perforce, Diversion, Unity VCS), Epic cloud tooling, Fab marketplace rules and revenue share

### Takeaway
Multi-User Editing (Concert) is documented and used in VP but has recurring community reports of brittleness and a 5.6 settings bug, with no 5.7/5.8 changelog found; Perforce remains the documented primary VCS with Diversion shipping a Fab-distributed plugin (UE 5.3-5.7) and Epic open-sourcing Lore (UEFN's VCS) under MIT at State of Unreal 2026. Fab (launched Oct 22, 2024) replaced the Unreal Marketplace with an 88% publisher share and a "Created with AI" labeling regime.

### Cited Findings
**Multi-User Editing (Concert)**
- Client-server model: a server hosts sessions; any Unreal Editor on the network connects to a shared workspace; sync strategy differs by asset type ("level changes sync immediately, while most asset types sync when saved"); saving a level grants a lock; Sequencer playback can sync across users, and opening remote Sequencers requires `Concert.EnableOpenRemoteSequencer` — [Epic docs: Multi-User Editing Overview](https://dev.epicgames.com/documentation/unreal-engine/multi-user-editing-overview-for-unreal-engine?lang=en-US); [Epic docs: Multi-User Editing](https://dev.epicgames.com/documentation/en-us/unreal-engine/multi-user-editing-in-unreal-engine); plugin indices [ConcertSyncClient](https://dev.epicgames.com/documentation/unreal-engine/API/PluginIndex/ConcertSyncClient), [MultiUserClient](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/PluginIndex/MultiUserClient)
- Aximmetry's guide: in 5.6 "you might have to use the Set as Default button to apply the settings due to a bug in Unreal Editor (5.6)" — [Aximmetry](https://aximmetry.com/learn/virtual-production-workflow/multi-machine-environment/advanced-information-and-features/multi-user-editing-with-aximmetry/)

## Licensing: EULA terms for tools/plugins and SaaS, 5% royalty, per-seat Unreal Subscription, Fab AI policy, AI training

Specific EULA language on SaaS products that drive the editor was not surfaced.

### Cited Findings
